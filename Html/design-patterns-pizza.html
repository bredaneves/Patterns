Factory Method vs Abstract Factory

O mesmo problema de pizzaria resolvido com cada padrão

Factory Method — o problema inicial
Você tem uma pizzaria e quer criar pizzas de tipos diferentes sem amarrar o código a uma classe específica.
Problema: o sistema precisa criar uma pizza, mas não quer saber qual pizza. Quem decide é a subclasse da pizzaria.

→ subclasses implementam

Java // === PRODUTO === interface Pizza { void preparar(); } class PizzaMargherita implements Pizza { public void preparar() { System.out.println("Pizza Margherita: massa fina, molho suave, mussarela"); } } class PizzaPepperoni implements Pizza { public void preparar() { System.out.println("Pizza Pepperoni: massa grossa, molho picante, pepperoni"); } } // === FÁBRICA (Factory Method) === abstract class Pizzaria { // Este é o Factory Method — subclasses decidem QUAL pizza criar abstract Pizza criarPizza(); void fazerPedido() { Pizza pizza = criarPizza(); // não sabe qual — não importa pizza.preparar(); System.out.println("Pedido pronto!"); } } class PizzariaItaliana extends Pizzaria { public Pizza criarPizza() { return new PizzaMargherita(); } } class PizzariaAmericana extends Pizzaria { public Pizza criarPizza() { return new PizzaPepperoni(); } } // === USO === Pizzaria p = new PizzariaItaliana(); p.fazerPedido(); // → Pizza Margherita: massa fina... Pizzaria p2 = new PizzariaAmericana(); p2.fazerPedido(); // → Pizza Pepperoni: massa grossa...
O ponto central: a classe Pizzaria chama criarPizza() sem saber o que vai receber. A subclasse é quem decide. Você está variando um único produto.
Factory Method — depois da expansão
O negócio cresceu. Agora tem PizzariaVegetariana. O que muda?
Regra de expansão: basta criar uma nova subclasse de Pizzaria e uma nova classe de Pizza. O restante do código não muda.
Java // Novo produto class PizzaVegetariana implements Pizza { public void preparar() { System.out.println("Pizza Vegetariana: massa integral, legumes grelhados"); } } // Nova fábrica — só isso class PizzariaVegetariana extends Pizzaria { public Pizza criarPizza() { return new PizzaVegetariana(); } } // O código cliente continua idêntico Pizzaria p = new PizzariaVegetariana(); p.fazerPedido(); // → Pizza Vegetariana: massa integral...
Perceba: a expansão foi simples porque cada pizzaria cria apenas uma coisa. Mas e se cada pizzaria precisasse também criar a bebida certa, a embalagem certa, o molho certo — tudo combinando entre si? O Factory Method começa a mostrar limitação aí. É exatamente esse problema que o Abstract Factory resolve.
Abstract Factory — o problema que ele resolve
Agora cada pizzaria tem um estilo completo: massa, molho e ingrediente — e precisam ser compatíveis entre si. Não mistura massa italiana com ingrediente americano.
Problema novo: não é mais um produto — são três produtos relacionados. A fábrica precisa garantir que todos sejam do mesmo estilo.

→ define

Java // === FAMÍLIA DE PRODUTOS === interface Massa { void descrever(); } interface Molho { void descrever(); } interface Ingrediente { void descrever(); } // Estilo Italiano class MassaFina implements Massa { public void descrever() { System.out.println("Massa fina"); } } class MolhoSuave implements Molho { public void descrever() { System.out.println("Molho suave"); } } class Mussarela implements Ingrediente { public void descrever() { System.out.println("Mussarela fresca"); } } // Estilo Americano class MassaGrossa implements Massa { public void descrever() { System.out.println("Massa grossa"); } } class MolhoPicante implements Molho { public void descrever() { System.out.println("Molho picante"); } } class Pepperoni implements Ingrediente { public void descrever() { System.out.println("Pepperoni"); } } // === ABSTRACT FACTORY === interface FabricaPizza { Massa criarMassa(); Molho criarMolho(); Ingrediente criarIngrediente(); } class FabricaItaliana implements FabricaPizza { public Massa criarMassa() { return new MassaFina(); } public Molho criarMolho() { return new MolhoSuave(); } public Ingrediente criarIngrediente() { return new Mussarela(); } } class FabricaAmericana implements FabricaPizza { public Massa criarMassa() { return new MassaGrossa(); } public Molho criarMolho() { return new MolhoPicante(); } public Ingrediente criarIngrediente() { return new Pepperoni(); } } // === MONTADOR — usa a fábrica sem saber qual é === class MontadorPizza { private FabricaPizza fabrica; MontadorPizza(FabricaPizza fabrica) { this.fabrica = fabrica; } void montar() { fabrica.criarMassa().descrever(); fabrica.criarMolho().descrever(); fabrica.criarIngrediente().descrever(); } } // === USO === MontadorPizza m1 = new MontadorPizza(new FabricaItaliana()); m1.montar(); // Massa fina / Molho suave / Mussarela fresca MontadorPizza m2 = new MontadorPizza(new FabricaAmericana()); m2.montar(); // Massa grossa / Molho picante / Pepperoni
O ponto central: o MontadorPizza não sabe qual fábrica está usando. Ele só chama os métodos. A fábrica garante que tudo que sair dela seja compatível — nunca vai misturar estilos.
Abstract Factory — depois da expansão
Chegou o estilo Vegetariano. O que muda?
Regra de expansão: crie os três novos produtos e uma nova fábrica que os agrupa. O MontadorPizza não muda nada.
Java // Novos produtos do estilo Vegetariano class MassaIntegral implements Massa { public void descrever() { System.out.println("Massa integral"); } } class MolhoErvas implements Molho { public void descrever() { System.out.println("Molho de ervas"); } } class LegunesTostados implements Ingrediente { public void descrever() { System.out.println("Legumes tostados"); } } // Nova fábrica que agrupa os três class FabricaVegetariana implements FabricaPizza { public Massa criarMassa() { return new MassaIntegral(); } public Molho criarMolho() { return new MolhoErvas(); } public Ingrediente criarIngrediente() { return new LegunesTostados(); } } // O MontadorPizza não mudou uma linha MontadorPizza m3 = new MontadorPizza(new FabricaVegetariana()); m3.montar(); // Massa integral / Molho de ervas / Legumes tostados
A garantia do padrão: é impossível montar uma pizza com massa italiana e molho vegetariano acidentalmente. A fábrica é a guardiã da consistência. Isso é o valor central do Abstract Factory.
Comparação final
Os dois padrões resolvem problemas diferentes. Use isso como guia de decisão.
Critério Factory Method Abstract Factory
Quantos produtos cria? Um único produto Uma família de produtos relacionados
Como varia? Subclasse sobrescreve um método Você troca a fábrica inteira
Garantia de consistência? Não — cada produto é independente Sim — a fábrica garante compatibilidade
Como expandir? Nova subclasse + novo produto Nova fábrica + novos produtos da família
Pergunta que responde "Qual subclasse cria este objeto?" "Como garantir que objetos relacionados sejam compatíveis?"
Exemplo pizzaria Cada pizzaria decide qual pizza fazer Cada pizzaria define massa + molho + ingrediente combinando
Regra prática para reconhecer na entrevista ou no código:

Se a fábrica tem um único método criar...() → provavelmente Factory Method.
Se a fábrica tem dois ou mais métodos e os produtos precisam andar juntos → Abstract Factory.
Onde você vai ver isso no mundo real:

Factory Method → Spring usa isso internamente para criar beans, conexões, handlers.
Abstract Factory → drivers de banco de dados (cada banco cria Connection, Statement e ResultSet compatíveis entre si), kits de UI (cada tema cria botão + menu + janela do mesmo estilo).
